编辑与删除 / Edit & Delete

按方向同步编辑 / Direction-aware edit sync

客服编辑 Topic 消息时，Bot 直接修改用户看到的消息；用户编辑时，Topic 会引用原消息并追加“用户修改为”的新内容。
Agent edits update the user's message in place; user edits are appended in the topic with a reference to the original.

删除双方消息 / Two-side deletion

回复需要删除的消息并发送 /delete 或 /del，Bot 会删除两端消息及删除命令。
Reply to a message with /delete or /del to remove it on both ends, including the command itself.

普通 Bot API 不会推送常规消息的删除事件，所以直接点 Telegram 的“删除”只影响当前一端。请使用回复命令触发双端删除；Telegram 的常规删除时限和管理员权限规则仍然适用。
The Bot API doesn't deliver deletion events for normal messages, so deleting via the Telegram UI only affects one side. Use the reply command for two-side removal; Telegram's deletion time limits and admin rules still apply.

管理员批量清理 / Batch Cleanup

双方清空，保留资料卡 / Clear both sides, keep profile card

在目标 Topic 发送 /clear，再发送 /clear confirm。Bot 会按每批 100 条清理用户端和管理端的对话消息，包括 /protect、/clear_user 等管理命令及 Bot 响应；Topic、会话映射与首条用户资料卡继续保留。
Send /clear then /clear confirm in the topic. The bot clears conversation messages on both user and admin sides in batches of 100, including admin commands like /protect, /clear_user and bot responses; the topic, session mapping, and the first profile card are kept.

/clear
/clear confirm
仅清空用户端 / Clear user side only

发送 /clear_user 并确认后，用户私聊页的映射消息会被清理，管理端 Topic 历史和资料卡均保留。
Send /clear_user and confirm to clear mapped messages in the user's DM; admin topic history and the profile card are kept.

/clear_user
/clear_user confirm

两种命令均只在管理员 Topic 生效。用户端命令菜单仅包含单条删除；Telegram 的常规删除时限和权限规则仍然适用。
Both commands only work in admin topics. The user-side menu only includes single-message deletion; Telegram's deletion time limits and permission rules still apply.

引用与内容保护 / Quotes & Content Protection

引用自动映射 / Automatic quote mapping

客服在 Topic 引用历史消息时，用户端会引用对应的消息副本；用户的引用也会映射回 Topic。
When an agent quotes a message in the topic, the user sees a quote of their own copy; user quotes map back to the topic.

禁止转发与保存 / No forwarding or saving

在当前用户 Topic 发送 /protect on，之后 Bot 发出的消息都会附带 Telegram 内容保护标记；使用 /protect off 关闭。
Send /protect on in a user's topic and all subsequent bot messages carry Telegram's protect-content flag; use /protect off to disable.

/protect on
/protect off
/protect

Bot 私聊采用逐条消息保护，开关状态和提示只显示在管理员 Topic；用户端不接收保护状态通知。Telegram 将 protect_content 定义为发送时参数，所以已有消息保持原状态，程序不替换或重发历史消息。
Protection applies per-message in DMs; status and hints only appear in the admin topic — users receive no notification. Telegram defines protect_content as a send-time parameter, so existing messages keep their original state and are never replaced or resent.

管理员命令菜单 / Admin Command Menu

程序启动时自动调用 Telegram setMyCommands。管理员在 Topic 输入 / 后会看到：
The bot calls Telegram setMyCommands on startup. Admins typing / in a topic will see:

  • /protect — 查看或设置后续消息保护 / View or toggle protection for subsequent messages
  • /delete — 回复消息后双端删除 / Delete a replied message on both ends
  • /clear — 清空双方消息并保留资料卡 / Clear both sides, keep profile card
  • /clear_user — 仅清空用户端 / Clear user side only
  • /allow_staff / /deny_staff — 按 Topic 授权或取消成员外发
  • /show / /hide — 单条消息对客可见或仅内部可见
  • /staff — 查看当前 Topic 授权成员
  • 可见性授权控制消息是否外发；群内 Topic 的浏览范围由 Telegram 群权限负责
  • /help — 显示完整说明 / Show full help

用户私聊输入 / 时只显示 /delete 和 /help。
Users only see /delete and /help in their private chat.
