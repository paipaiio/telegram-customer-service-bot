首次配置

  1. 通过 BotFather 创建 Bot 并取得 Token。
  2. 创建私有超级群，开启“话题 / Topics”。
  3. 把 Bot 设为管理员，并授予管理话题、发送消息和删除消息权限。
  4. 复制配置文件并填入 Token 与群 ID。
cp .env.example .env

# 编辑 .env
BOT_TOKEN=123456789:YOUR_TOKEN
SUPPORT_GROUP_ID=-1001234567890
DATA_FILE=./data/forumdesk.json

Topic 没有独立头像。基础版会把用户头像作为 Topic 的第一张资料卡图片，视觉上实现接近的效果。

编辑与删除

按方向同步编辑

客服编辑 Topic 消息时，Bot 直接修改用户看到的消息；用户编辑时，Topic 会引用原消息并追加“用户修改为”的新内容。

删除双方消息

回复需要删除的消息并发送 /delete 或 /del，Bot 会删除两端消息及删除命令。

普通 Bot API 不会推送常规消息的删除事件，所以直接点 Telegram 的“删除”只影响当前一端。请使用回复命令触发双端删除；Telegram 的常规删除时限和管理员权限规则仍然适用。

管理员批量删除整段对话

在目标 Topic 发送 /clear 查看危险操作确认，再发送 /clear confirm。Bot 会按每批 100 条删除用户端映射消息，删除整个 Topic，最后清理本地会话映射。

/clear
/clear confirm

该命令只在管理员 Topic 生效。用户端命令菜单不包含整段删除；Telegram 对用户私聊消息的删除时限仍然适用。

引用与内容保护

引用自动映射

客服在 Topic 引用历史消息时，用户端会引用对应的消息副本；用户的引用也会映射回 Topic。

禁止截图、转发与保存

在当前用户 Topic 发送 /protect on，之后 Bot 发出的消息都会附带 Telegram 内容保护标记；使用 /protect off 关闭。

/protect on
/protect off
/protect

Bot 私聊采用逐条消息保护，开关状态和提示只显示在管理员 Topic；用户端不接收保护状态通知。用户自己发出的原始消息和已有消息维持原状态。

管理员命令菜单

程序启动时自动调用 Telegram setMyCommands。管理员在 Topic 输入 / 后会看到：

  • /protect — 查看或设置内容保护
  • /delete — 回复消息后双端删除
  • /clear — 双向删除整段对话
  • /help — 显示完整说明

用户私聊输入 / 时只显示 /delete 和 /help。

项目结构

cmd/forumdesk/       程序入口
internal/app/        长轮询运行器
internal/bot/        Topic 双向路由
internal/config/     环境变量配置
internal/store/      JSON 原子持久化
internal/telegram/   Telegram Bot API 客户端
data/                运行数据（自动创建）

当前基础能力与边界

已经具备

  • 文本、图片、语音、视频、文件等消息复制
  • 客服与用户双向引用映射
  • 按 Topic 开关禁止转发/保存
  • 单条双端删除、管理员整段清理
