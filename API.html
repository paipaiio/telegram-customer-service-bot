ForumDesk Web API v1

网页客服接入 Telegram Topic

网页访客通过 REST API 发起会话，ForumDesk 在 Telegram 超级群创建独立 Topic。客户消息由 Bot 发入 Topic，已授权客服的回复则进入网页轮询队列。

快速开始

1. 服务端建立会话

网站后端使用集成密钥创建会话，取得一次性返回的 visitor_token。

2. 浏览器收发消息

只把当前访客的会话 ID 和访客 Token 交给前端，前端用它发送和轮询。

WEB_API_KEY 只放网站后端；浏览器仅持有单会话 visitor_token。

认证模型

凭据用途传递方式
WEB_API_KEY网站后端创建会话Authorization: Bearer API_KEY
visitor_token当前访客收发消息Authorization: Bearer VISITOR_TOKEN

POST/api/v1/conversations

创建网页会话和对应 Telegram Topic。此接口使用集成密钥。

curl -X POST "$BASE/api/v1/conversations" \
  -H "Authorization: Bearer API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "visitor_name": "Ada",
    "email": "ada@example.com",
    "external_id": "customer-7",
    "page_url": "https://www.example.com/pricing"
  }'

201 Response

{"data":{"id":"wc_...","visitor_token":"wv_...","status":"open","created_at":"2026-09-07T10:00:00Z"}}

POST/api/v1/conversations/{id}/messages

访客发送 1–4000 字符的文本。可选的 reply_to_message_id 会在网页与 Telegram Topic 两端保留引用关系。

await fetch(`${BASE}/api/v1/conversations/${conversationId}/messages`, {
  method: "POST",
  headers: {
    "Authorization": `Bearer ${visitorToken}`,
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    text: "我想了解商务方案",
    reply_to_message_id: "wm_..." // 可选
  })
});

GET/api/v1/conversations/{id}/messages

使用递增游标轮询：after 默认 0，limit 范围 1–100。

const response = await fetch(
  `${BASE}/api/v1/conversations/${conversationId}/messages?after=${cursor}&limit=50`,
  { headers: { "Authorization": `Bearer ${visitorToken}` } }
);
const payload = await response.json();
cursor = payload.meta.next_cursor;

direction 为 customer 或 staff；reply_to_message_id 指向被引用的可见消息。当管理员隐藏已发消息时，队列返回 event: message_hidden 与 target_message_id，前端据此移除已渲染消息。

Telegram 成员可见性

命令作用
/allow_staff管理员回复成员消息，允许其后续发言自动对客可见
/deny_staff取消该成员在当前 Topic 的自动对客可见
/staff查看当前 Topic 的授权成员
/show回复某条内部消息，单独对客可见
/hide回复某条已发消息，改为仅管理端可见

群管理员发言默认对客可见；普通成员默认只留在 Topic 内部。授权按 Topic 隔离；管理员和已授权成员在 Topic 内使用 Telegram 原生回复时，网页端也能取得引用消息 ID。

这些命令控制消息是否外发给客户；成员能看到哪些 Topic 仍由 Telegram 超级群本身的成员与权限配置决定。

错误与限流

JSON 错误格式
{"error":{"code":"validation_error","message":"..."}}
状态码

400 JSON/游标错误 · 401 凭据错误 · 422 参数错误 · 429 限流 · 502 Telegram 上游错误

默认每个集成密钥/会话每分钟 60 次，通过 WEB_RATE_LIMIT_PER_MINUTE 调整。
